## 使い方

- **いちばん上の「★ いちばん大事な決まり」が最優先。** その中でも **★0 経過報告（最長3分・表で）** は、どの場面でもいちばん上。そのうえで作業の最初に、今が 場面A（カンプから作る）／B（カンプなしで作る）／C（作った画面をFigmaに書き出す）のどれかを見きわめ、その場面の決まりから守る。
- 次に「0. 安全のための決まり」と「1. いつでも」を読み、そのあと今回の作業に合う節を読む（カンプから作るなら「2」、Figmaに書き出すなら「3」、調整パネルを使うなら「6」など）。
- 決まりの重さは3段階。**★**＝いちばん大事な決まりに入っているもの（最優先）、**〔絶対〕**＝破ると事故や作り直しになるもの、印なし＝基本は守る（理由があれば相談して外せる）。
- 各ルールの下の「元の番号」は、仕分け棚の番号。経緯を追う時に使う。
- ルールを足す・変える時は、ヒデさんと決めてからこのファイルを直し、[settings/docs/README.md](../README.md) の索引も見直す。★の節は自動で出す仕掛けがこのファイルから直接読むので、`<!-- 〜:start -->` `<!-- 〜:end -->` の印は消さない。
- **このルール集は「これからの進め方」の決まり。** ここから外した決まりに沿って作られた、今あるサイトやアプリの作りは変えない。

## ★ いちばん大事な決まり（最優先）

<!-- report:start -->
### ★0 経過報告（どの場面でもいちばん上・〔絶対〕）
- **作業中は、最長3分ごとに経過報告する。** 前の報告から3分を過ぎたら、手を止めてでも報告します。裏で動いている作業を待っている間も同じです。
- **報告は3つの見出しの表で出し、中身は箇条書きにする。** 文章でつなげず、1つのことを1行に短く書きます。見出しが同じ行が続く時は、2行目から見出しの欄を空けます。
- **各行の頭に、状態が一目で分かる絵文字を付ける。** ✅ 終わった／🔄 いまやっている／⬜ これから／❓ 確かめたいこと／⚠️ 困っていること・注意

| | 中身 |
|---|---|
| 今やっていること | 🔄 いま手を動かしていること |
| 終わったこと | ✅ 前の報告から終わったこと |
| | ✅ （2つ目があれば1行ずつ足す） |
| これからやること | ⬜ 次にやること（見込み時間） |
| | ⬜ その次にやること |

- ❓ 確かめたいことや ⚠️ 困っていることがある時は、表の下に1行ずつ書きます →1-4

### 場面A　カンプから作る
- **A1 カンプを完全に再現する。** 難しくても簡略化せず、寄せ切ってから見せます。取れない値や決まっていない所（動き・hover・画面幅を変えた時など）は推測で埋めず、作る前に表にして聞きます。聞けない時だけ「仮置き」と印を付けて進め、報告で一覧にします →1-1・1-9
- **A2 コードより先に、全要素のスペック表を作る。** 書体・ウェイト・サイズ・行間・字間・色・線幅・角丸・影・余白・gap・幅の決め方（Fixed／Hug／Fill）を、Figmaの設定値で読みます。枠の幅やスクショから逆算しません →2-1・2-2
- **A3 4と8の倍数だけは、カンプより優先する。** 4-7の表で倍数の決まりがある項目（文字サイズ・サイズ・余白・角丸）の半端な値は4か8の倍数（10px以下は2刻み・文字は14と18も可）に寄せ、報告の表に「カンプ値→採用値」で書きます。字間と位置はカンプの値のままです →4-7
- **A4 完了は、測った表で言う。** 箇所／カンプ値／実装値／一致 を並べ、ずれが残る間は完了と言いません →1-3

## 0. 安全のための決まり

守らないと、別のサイトの上書き・営業同期の停止・情報漏れにつながるもの。どの作業でも守る

0-1. **★〔絶対〕デプロイ前に、送り先のVercelのプロジェクト名を確かめる**  
   デプロイするフォルダの設定に書かれたプロジェクト名を見て、狙いどおりかを確かめます。違うフォルダからデプロイすると、新しいプロジェクトが勝手にできたり、本番を上書きしたりするためです。
   <sub>元の番号: 249</sub>

0-2. **〔絶対〕Vercelに登録する鍵や設定値は、読み返す物だけ秘密扱いを外す**  
   あとで中身を取り出して確かめたい値だけ、登録の時に秘密扱いにしない指定を付けます。Vercelの操作ツールの今の版では最初から秘密扱いになり、中身が入っていても取り出すと空に見えるためです。
   <sub>元の番号: 250</sub>

0-3. **★〔絶対〕変更を記録する前に、記録に付くメールアドレスを確かめる**  
   記録に付くのがヒデさんの名前とGmailのアドレスになっているかを見ます。パソコン名から自動で付いたようなアドレスだと、Vercelがデプロイを断るためです。
   <sub>元の番号: 270</sub>

0-4. **★〔絶対〕網走とAnyFlowのV1.0を残したブランチは、消さず上書きもしない**  
   網走とAnyFlowのV1.0のブランチは消さず上書きもせず、網走の更新はmainに積んで、こうしたブランチを増やした時はClaudeへの指示書の表に1行足します。あの時の状態に戻したい時に使うためです。
   <sub>元の番号: 273</sub>

0-5. **〔絶対〕個人情報を扱うGitHubの保管場所は、最初から非公開にする**  
   データを入れる前に保管場所が公開か非公開かを確かめ、ローカルで使う本番データの写しは記録の対象外の場所に置きます。公開の保管場所に、控えのデータを毎日記録していた事故があったためです。
   <sub>元の番号: 282</sub>

0-6. **★〔絶対〕営業同期のNotionのデータベースとページは、消さず名前も変えない**  
   データベース3つと通知ページ1つは消さず名前も変えずに残し、中の1件ずつのページだけは消してよいことにしています。営業同期の仕組みが、この4つを番号で直接使っているためです。
   <sub>元の番号: 305</sub>

0-7. **APIキーなどの鍵は、中身を資料に書かない**  
   鍵の中身そのものは資料に書かず、ローカルの設定ファイルと、暗号をかけた本番用の設定ファイルだけで管理します。
   <sub>元の番号: 263</sub>

0-8. **Notionのプロパティの種類をわざと変えたら、営業同期の定義も合わせる**  
   わざと種類を変えた時は、営業同期のプログラムにあるプロパティの定義を新しい種類に書き換えます。名前の変更や追加、削除には自動でついていけますが、種類の変更だけは同期が止まってしまうためです。
   <sub>元の番号: 306</sub>

0-9. **営業同期に新しい媒体タグを足す時は、Notion側の選択肢も足す**  
   媒体の一覧ファイルに新しいタグを足したら、Notionの媒体の欄にも同じ名前の選択肢を用意しておきます。
   <sub>元の番号: 315</sub>

0-10. **家庭訪問アプリのデータは、Googleシートでなくアプリで書き換える**  
   Googleシートは見るだけにして、個人情報が多いので共有する相手にも気をつけます。シートはアプリのデータを写したもので、書き換えても次の同期で消えるためです。
   <sub>元の番号: 316</sub>

0-11. **外部サービスの鍵はブラウザ内だけに保存し、中継サーバーには残さない**  
   カンペ連動プレゼンでは、Notionにつなぐ鍵を使う人のブラウザの中に保存し、Vercel上の中継サーバーは受け渡すだけで鍵を残さない作りにしています。
   <sub>元の番号: 325</sub>

## 1. いつでも

進め方・質問・報告・話し方。どの作業でも毎回守る

1-1. **★〔絶対〕自分で仮に決めた所は、黙って埋めず「仮置き」と印を付けて伝える**  
   取れなかった値や決まっていない所を自分で決めた時は、その時点で「ここは取れなかったので、この値を仮に置きました」と書き添え、報告で一覧にします。カンプから作る時は、仮に決める前にまず聞きます（★A1）。事故の原因は、仮で決めたことを黙っていたことだったためです。
   - Figmaから素材が取れない時は手持ちで代用し、仮置き一覧に書く：Figmaから素材を取り出せなかった時は手持ちの素材で代わりを置き、仮のコピーや配色と一緒に、説明資料の仮置きの表へ書き残します。推測で埋めたのではなく、取れずに代用したのだと後から分かるようにするためです。
   <sub>元の番号: 004</sub>

1-2. **★〔絶対〕質問する時は、選択肢とおすすめと理由をそろえて出す**  
   こう受け取ったという前提を先に書いてから、ボタンで選べる形で聞き、一度決まったことは蒸し返さないようにします。「どうしますか」とだけ聞くと、判断をヒデさんに丸投げすることになるためです。
   <sub>元の番号: 009</sub>

1-3. **★〔絶対〕確認したと言う時は、測った数値を表で示し、ずれが残る間は完了と言わない**  
   書体・字間・余白は目で見ても分からないので、ブラウザで実際に効いている値や文字の幅を測ります。カンプから作った時は『箇所／カンプ値／実装値／一致』の表で合否を付け、ずれが残る間は完了と言いません。カンプから取れなかった項目も『取れず・こう仮定』として表に残します。
   - カンプと合っているかは、Figmaの画像と実際の画面を並べて見比べる：Figmaから撮ったカンプそのものの画像と、実際に表示した画面を撮った画像を、縦に並べて1枚にして比べます。
   <sub>元の番号: 019・047</sub>

1-4. **★〔絶対〕作業中は、最長3分ごとに、表で経過報告する**  
   「今やっていること／終わったこと／これからやること（見込み時間）」の3つの見出しの表で、聞かれる前にこちらから伝えます。表の中身は文章でつなげず、1つのことを1行の箇条書きにし、行の頭に状態の絵文字（✅ 終わった／🔄 いまやっている／⬜ これから／❓ 確かめたいこと／⚠️ 注意）を付けます（2026-09-27 ヒデさんの指示）。前の報告から3分を過ぎたら報告します。確認なしで進める設定の時も、裏で動いている作業を待っている時も同じです。確かめたいことがある時は、表の下に1行で書きます。（ヒデさんの指示 2026-09-27：どの場面でもいちばん上の決まりにする・最長3分・表で）
   - 前の報告から3分たったら、自動の合図を見て報告する：作業の前に段取りを出して、段が終わるごとに報告します。前の合図から3分たつと、自動で合図が出る仕掛けを入れてあります（2026-09-27〜）。「最大3分」と決めた後も、黙ったまま3分を超えた場面が172回あったためです。
   <sub>元の番号: 021</sub>

1-5. **〔絶対〕自分のミスの後始末をヒデさんに頼まない**  
   失敗したら手を止めて被害を自分で調べ、直せる分は直し、直せない分だけ理由を短く伝え、ヒデさんに操作を頼むのは最後の手段としてワンクリックで済む形にします。
   <sub>元の番号: 028</sub>

1-6. **★〔絶対〕途中の一言や作業の説明も、日本語で書く**  
   最後の答えだけでなく途中経過や操作の説明文まで日本語で書き、書く直前に確かめて、使うAIが切り替わってもそのまま続けます。
   - 返事を出す前に、日本語になっているかを自動で確かめる（自動の仕掛けを入れる前提。まだ未設定）：返事を出す時に日本語の割合を自動で確かめる仕掛けを入れ、モデルが替わった時と会話が要約された直後は、最初の3回の返事を自分で点検します。文書の決まりだけでは、途中の報告が英語になることが続いたためです。
   <sub>元の番号: 037</sub>

1-7. **★〔絶対〕関西弁で噛み砕き、専門用語は例え話とセットで**  
   「これは〇〇みたいなもんです」のように日常の例えで言い換え、関西弁でかみ砕いて結論から話します。開発の言葉が多い、もう少し分かりやすく、と何度も言われているためです。
   - 報告では内部の番号や名前を出さず、他社の人にも分かる言葉で書く：Figma内部の番号や設定の名前、相手にとって意味のない個数は出さず、「消えた文字を戻しました」のような言い方で書きます。
   <sub>元の番号: 038</sub>

1-8. **★見た目や動きは、触れるmockか調整パネルで決める**  
   演出が未定ならmockを3から5案、数値を詰めるだけなら調整パネルを出し、言葉ではなく実際に触って選んでもらいます。選択肢を多く出した案件ほど、同じ直しの繰り返しが少なかったためです。 mock はダミーの適当なデータではなく、デザインを忠実に再現したデータで作り、本番・ローカルを問わずバリエーションを用意します。（ヒデさんの要望 2026-09-27）
   <sub>元の番号: 002</sub>

1-9. **★決まっていない所は、作り始める前に表にして、こちらから聞く**  
   ヒデさんは画面を見ても何が未決か分からず、聞かれなければ全部決まったと受け取ります。作る前に、資料から取れた値と、取れずに仮で決めた値を分けた表を見せます。動き・間合い・順番・hover・画面幅を変えた時・エラー時は資料に無いことが多いので、必ず表に入れます。
   - 動きの指定が無い時は、Claude が決めて作るか、絵コンテをもらうかを先に聞く：カンプが動きを決めていない時は、Claude が判断して作るか、絵コンテを用意してもらうかをヒデさんに確認します。絵コンテがある時は、それを基本として忠実に再現します。（ヒデさんの要望 2026-09-27）
   <sub>元の番号: 006・012</sub>

## 4. デザインシステムを作る・整える時

4-1. **〔絶対〕使うウェイトは全部フォントの読み込み範囲に入れる**

   <sub>元の番号: 087</sub>

4-2. **デザインシステム整備は、洗い出し→統合→命名→トークン化の順で進める**  
   似た値を寄せると1から2px動く所が出ることを先にヒデさんと確認し、戻れる控えを作ってから、値を自動で数え、まとめ、名前を付けてトークンとして1か所で管理し、資料にする順で進めます。
   - 値の洗い出しは、本番とmockを分けて自動で数える：色や角丸、影などの値が何回使われているかを、mockを除いた本番の画面だけで自動で数えます。目で探すと見落とし、mockまで混ぜると数が10倍ほどずれることがあるためです。

   - 一度も使われていないトークンは、定義ごと消す：本番の画面で何回使われているかを実際に数えて消すかどうかを決め、網走V3ではこうして17個を消しています。
