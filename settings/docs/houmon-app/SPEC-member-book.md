# メンバー情報（メンバータブ）の仕様

> 決めた日: 2026-10-26（ヒデさんと質問しながら固めた）。作業場所: houmon-app の `update/member-book` ブランチ。
> 狙い: 家庭訪問アプリを軸にしたまま、「訪問しない人の情報も忘れないように残せる」メンバー情報のアプリにもする。
> 作りは「名簿は1つ・区分で分ける」「情報は決まった見出しに振り分ける」のシンプルな形にして、あとから広げやすくする。

## 決まったこと

| 項目 | 決まり |
|---|---|
| 入れる人 | 名簿は1つのまま（今の男子部のメンバーと同じ）。**「家庭訪問する／しない」の区分は持たない**（2026-10-26 ヒデさん「訪問しない人は訪問ログを記入しなければいい」→ Claude も賛成：決めることが減る・名簿だけの人は住所が無いことが多く地図も散らからない・要ればあとから1人ずつの印を足せる）。気をつける所：住所がある名簿だけの人も地図・ホームの一覧・ダッシュボードの未訪問に入る |
| 区分 | **男子部（前の「一般」）・ヤング・女性部・壮年部** の4つ（2026-10-26 ヒデさん「女性部・壮年部が必要。4つなのでプルダウン」）。**マップ（地図・地図の一覧）とダッシュボードは男子部とヤングだけ**（同日「マップの家庭訪問は男子部・ヤングしか扱わないので拡張しない」）。ホーム（名簿）は全員で、見出しのプルダウンで すべて・男子部・ヤング・女性部・壮年部 を選ぶ（男子部はヤングも含む＝仮置き）。名簿の行の名前の横に、女性部・壮年部は灰色の印。新規登録・おまかせ入力の区分はプルダウン。データは文字のままなので SQL は要らない |
| 名簿の並べ方 | **すっきり一覧**（1行に1人：かな・名前・ヤング・所属・›）（2026-10-26 ヒデさん決定・見本の案2） |
| AI の案の確かめ方 | **1件ずつ確かめる＋編集で動かす**：4つの見出しはいつも固定で並べ、中身を1件ずつ ✓ で入れる／外す。右上の「編集」を押すと、各行の右のつまみ（十字）を持って 別の見出しへ動かせる・並びも変えられる（例：特徴 → 印象的な出来事）。空の見出しは編集中は点線の受け皿になる（2026-10-26 ヒデさん「セクションが固定で、その中身を編集ボタンでドラッグアンドドロップ」） |
| 情報の見出し | **家族構成・特徴・印象的な出来事・その他** の4つ |
| 見出しの育ち方 | 家族構成・特徴・その他は「今の姿」を AI がまとめ直す（食い違えば新しい方）。**印象的な出来事だけは消さずに日付つきで積む** |
| 話して入れる入口 | **ホームの＋（おまかせ入力）だけ**。家庭訪問の流れの中で、AI が「訪問の記録」と「情報の更新」に振り分ける |
| AI の更新の仕方 | **案を見せてから保存**（見出しごとに足す分を見せる・話した原文も残す・やり直せる） |
| 今の「情報」の文 | AI で4つの見出しへ**自動で振り分ける**。元の文は各人のページに「振り分け前の文」として残す。振り分けの前に何人か分を見本で見せる |
| 下のタブ | **ホーム（名簿・/）・マップ（地図・/map）・カレンダー・ダッシュボード**（2026-10-26 ヒデさん「メンバーをホームに、地図のピンのボタンをマップに」）。1人のページ（/members/〜）を開いている時はホームが選ばれた形。前の住所 /members はホームへ転送。アプリを開くと最初はホーム |
| 設定 | 地図の右上（前の「地図の見た目の切り替え」ボタンの場所）に置く。地図の見た目の切り替えは、いったん無くす |
| メンバータブの名簿 | ホームの一覧と同じ絞り込み（見出しで男子部／ヤング・本部・部・地区・並び替え）。区分の絞り込みを足す |
| 1人のページの形 | **いちばん上は「名簿｜訪問ログ」の2つのタブだけ**（最初は名簿。タブの中にタブは作らない）（2026-10-26 ヒデさん「タブが混在しているのでシンプルに」）。上の共通の所＝戻る・名前・読み仮名・ヤング・ブックマーク・編集 |
| 名簿のタブ | 今の詳しい画面の情報を全部（今の本物の部品をそのまま使う・2026-10-26 ヒデさん「モックのデザインが違うので本番と合わせて」で本物の画面に作った）：基本情報（本部・部・地区／住所と地図／自宅TEL／携帯／生年月日と年齢／入会月日／職場／役職／同居／教学／備考）・ステータスの○×（御安置・勤行・聖教・広布・活動・教学・創牙）・情報の4つの見出し（AI の案と同じ固定のカード・「編集」でつまんで動かす）・情報の写真・このメンバーを削除 |
| 訪問ログのタブ | 訪問の記録を別に管理：訪問の記録の一覧（今の本物の部品のまま）・住所不明の対応メモ（住所不明の訪問がある時）。件数はタブの名前に出す |
| 名簿の人の登録の入口 | 足さない：ホームの＋の「メンバーを登録」で足りる（新しく登録した人は名簿から始まる）（2026-10-26 決まった中身から決めた） |
| 版の番号 | 大きいアップデートなので、main に乗せる時に v2.0.0 にする（仮置き） |

## データの持ち方（2026-10-26 作った・SQL は `houmon-app/sql/2026-10-26-member-info-sections.sql`）

- メンバーに `info_sections`（jsonb 1つ）を足す：`{ family: [文], trait: [文], event: [{date, text}], other: [文] }`。見出しを増やす時も列を足さずに名前を1つ足すだけ
- `info_sorted_at`（最後に振り分けた・直した時）
- まだ振り分けていない人は空。今の `info` の文はそのまま残す（＝振り分け前の文）
- 区分（家庭訪問する／しない）は持たない

## 見本

ローカル: `http://localhost:3098/mock/member-book`。2026-10-26 ヒデさん「一覧で見ると見にくい。遷移してその案を確かめる形に」で、
**一覧のページ（決めることごとに案を並べる・決定／未定の印）→ 押すと その案がスマホいっぱいの本物の大きさで開く**（`/mock/member-book/view?s=段&p=案`。上の黒い帯で一覧に戻る・同じ段の別の案へ移る）形にした。

| 段 | 決めること | 状態 |
|---|---|---|
| 1 | 名簿の並べ方 | 決定：すっきり一覧 |
| 2 | 1人のページの見せ方 | 決定：名簿｜訪問ログの2つのタブ |
| 3 | AIの案の確かめ方 | 決定：1件ずつ確かめる＋編集で動かす（触って動かせる） |

見本の仮置き（本番では AI とデータベースが受け持つ）:
- 4つの見出しへの振り分けは、言葉の手がかりで仮に分けている
- 話した原文は、その人の情報の2行を「話した」形にしたもの（作り話は足していない）。訪問日は 10/26 として見せている
- 個人の情報はファイルに書き込まず、開いた時にデータから読む

## 作った物（2026-10-26・v1.4.0 で本番へ）

| どこ | 中身 |
|---|---|
| 1人のページの名簿のタブ | 「情報」の段＝4つの見出しのカード。鉛筆で編集（文を直す・足す・消す・つまんで別の見出しへ動かす）→ ✓ で保存。まだ振り分けていない人は「情報の文をAIで振り分け」→ AI の足した分を紫で見せ、✓ で保存／× でやめる。その下に元の文と写真（振り分けた人は「振り分け前の文・写真」） |
| おまかせ入力の確認画面 | 「情報に足す」＝話した内容を AI で4つの見出しに振り分け、今ある見出しに無い分だけを案に並べる。✓ で入れる／外す・「編集」でつまんで動かす。登録で見出しに足す（今ある行は消さない・出来事は日付つきで前に積む）。誰の記録かを変えると振り分け直す |
| 設定 › 情報の振り分け | 今ある情報の文を まとめて振り分ける：3人分の見本を見る → 「この形で全員に入れる」。途中で止まっても、もう一度押すと残りから続く |
| AI のしくみ `/api/info-sort` | ログインした人だけ。家族構成・特徴・その他は今の姿にまとめ直し、出来事は新しい分だけ日付つきで返す。手元（AIの鍵が無い）では言葉の手がかりの仮の振り分けを返す |

仮置き：おまかせ入力では、AI がまとめ直した「今の姿」で今ある行を書き換えず、無い分を足すだけにした（知らないうちに消えたり変わったりしないように）
