## 1. 何を作っているか

**網走市の観光サイト**（リブランディング案）。コンセプトは **「な〜んにもない、たまらない」**＝何もない網走で“ぼーっとする”時間を届ける。
トンマナは白基調・Noto Sans JP の Thin／ExtraLight・余白多め・ブラーでふわっと溶ける演出・ブランドの青 #0070C9。デザインの元は Figma（fileKey `jSLFEubHMoy3Hxgcw1AZuR`「works」）。

| 版 | フォルダ | 本番 URL | 位置づけ |
|---|---|---|---|
| V1.0 | abashiri/v1 | https://abashiri-site.vercel.app | 公開版（2026-08-21 に Figma 15059 系の前のデザインへ戻して固定）。凍結ブランチ `abashiri-v1.0` も残す |
| V2 | abashiri/v2 | https://abashiri-site-v2.vercel.app | プレゼンで見せた版（保全） |
| **V3** | **abashiri/v3** | **https://abashiri-site-v3.vercel.app** | **いま作っている版**（2026-09-14 に V2 のコピーから開始） |

V3 の中身:
- **トップ（/）**：キービジュアル（作字・人物イラスト・カモメ）→ メッセージ「網走は何もない。」→ ぼーっとスポット（能取岬・サンゴ草・流氷クルーズ・ひまわり畑の4枚、1スクロール＝1枚）→ 素朴なグルメ（5場面目・見出し＋4店のカルーセル）→ 体験セクション「意外とオモロい、網走。」（4件）→ 共通フッター
  - PC は 1512×982 の紙を画面に合わせて縮小表示。中の箱が独自の慣性でスクロール（components/TopPage.tsx）
  - スマホ・縦長タブレットは別の作り（components/MobileTop.tsx）。1画面ずつブラーで切り替わる場面式
- **ぼーっと体験（/experience）**：導入メッセージ → 場所えらびのカルーセル（最初は流氷クルーズ・動画があるのは流氷だけ）→ 動画でぼーっとする（ぼーっとTips・ぼーっとタイマー・環境音）
- **詳細ページ（テンプレ）**：/spot/<名前>（notoro・sango・ryuhyo・himawari・kangoku・ryuhyokan・canoe・washi）、/gourmet/<名前>（yokoyama・matsuo・darumaya・tonton）。中身は網走の観光サイトの情報を流し込み・文章は作文
- **調整パネル**：右下の透明な四角で出す隠しパネル。演出の数値や案を、ヒデさんがその場で触って決めるための道具

## 5. 守ってほしいルール（全文は RULES.md。食い違ったら RULES.md が優先）

**報告と話し方**
- 作業中は最長3分ごとに経過報告。「今やっていること／終わったこと／これからやること」の表で、中身は1行ずつの箇条書き、行頭に ✅🔄⬜❓⚠️
- 日本語で、関西弁でかみ砕く。専門用語は例え話と一緒に。結論から
- VOICEVOX（speaker=1・speedScale=1.3・100字以内・英単語はカタカナ）で、受けた時・始める時・節目・完了・エラーを知らせる
- 完了の報告は、測った数値の表で。目で見ただけの「確認しました」は禁止
- 仕組みを説明する時は、図やスクショを添える

**進め方**
- 指示は音声入力なので、誤字を疑う。「『ここ』＝◯◯と解釈して進めます」と1行宣言してから始める
- 取れなかった値や決まっていない所を、黙って埋めない。仮で決めたら「仮置き」と明示して一覧に
- 質問は AskUserQuestion で、選択肢・おすすめ・理由をそろえる
- 見た目や動きは言葉で聞かず、調整パネルか触れる mock で決めてもらう。案を出す時は、本物のデザインとデータで作る
- 頼まれた所だけ変える。今ある案・演出・部品を勝手に消さない。「〇案で採用」と言われたら、ほかの案を消すか聞く
- 途中で別の依頼が来たら、今の作業をやり切ってから。依頼は受けた時点で TASKS.md に書き足す
- 頼まれていない説明文を画面に足さない
- 自分のミスの後始末をヒデさんに頼まない

**デザインと調整パネル**
- 文字サイズ・サイズ・余白・角丸は4と8の倍数（10px以下は2刻み・文字は14と18も可）。見た目の数値を足したら、次の検査で外れ0件を確かめる：
  `node settings/design-check/design-check.mjs abashiri/v3/app abashiri/v3/components`
- 見た目や既定値を変える時は、値の住み家を全部そろえる（コードの既定・globals.css・TopTunePanel の既定・public/tune-defaults.json）。古い保存値を入れてリロード2回で実測してから報告
- 調整パネルの値は案ごと×PC/スマホごとに独立（部品が自動）。項目を足したら、全部のつまみの効き目と漏れを検査して表で報告し、どこで操作するかも伝える

**不具合**
- 直す前に FIXLOG を症状の言葉で検索。直したら1行書き足す
- 同じ「直ってない」が2回来たら手を止め、原因の候補3つと確かめ方を先に出す

**デプロイと git**
- 開発中はローカルの URL を案内。デプロイは「デプロイ」と言われた時だけ、まとめて1回
- 前に Vercel のプロジェクト名（abashiri/v3/.vercel/project.json が abashiri-site-v3）と、コミットのメール（dosanko.design@gmail.com）を確かめる
- 手順：/tmp/ab-prod-build に本番と同じビルド → next start -p 3199 で確認 → npx vercel --prod --yes → 本番 URL で確認 → 1日100回の枠の何回目かを伝える
  - ビルド用の node_modules はシンボリックリンク不可（cp -Rc で複製）
  - Google フォントを取りに行くので、制限環境の外で実行する
- main 一本。凍結ブランチ abashiri-v1.0 は触らない。自動保存はコミットだけ。push はデプロイの時に Claude がする

## 6. 作りの要点（触る前に知っておくこと）

- 開発サーバーは localhost:3095（launch.json の abashiri-v3）
- ページ移動は components/PageTransition.tsx を必ず通す（リンクは自動・ボタンは navigateTo()）。router.push や window.location を新しく書かない
- PC トップのスクロールを止める時は window.__abashiriScrollGate/GateTop の関所に書く。張った部品は、消える時に片付ける
- 調整パネル：public/tune-panel.js（共通部品 v2.0.0 のコピー）。トップは TopTunePanel.tsx、詳細は SpotDetailPage.tsx
  - 案ピルと同じ見出しの中のつまみは案ごと。見出しより前のピルならタブ全体が案ごと
  - 文字サイズのつまみには grid:'fontSize'
  - 2026-09-28 に最新の共通部品（v2.1.0）を入れた。共通部品（settings/tune-panel/tune-panel.js）を直したら、網走へは cp で同じファイルにする（本体の自動検査 `node settings/tune-panel/test/check.mjs` を通してから）
- スマホモードの QR・実機への反映は public/phone-mode.client.js＋components/phoneMode.ts。中継サーバーは使う時だけ：
  `cd settings/tune-panel/phone-mode && (test -d node_modules || npm install) && PAGE_PORT=3095 SYNC_PORT=8780 node server.mjs`
- 画面の検査は design-gallery の Playwright（swiftshader）を借りる。スクロールの「1回のはじき」は、ページの中から 16ms 間隔で WheelEvent を送る（mouse.wheel は間隔が空きすぎる）
