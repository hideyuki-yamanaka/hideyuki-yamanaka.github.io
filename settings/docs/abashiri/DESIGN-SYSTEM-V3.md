### ブラーの落とし穴（実測で分かったこと・2026-09-16）

1. **`backdrop-filter` は毎フレーム値を変えると極端に重い。**
   ページ遷移の演出では**ブラー量は固定**して、幕の不透明度だけを動かしている。
2. **`filter` / `backdrop-filter` が付いた要素は合成レイヤーになり、その縁が
   隣の同じ色のセクションとの境目に薄い線（ヘアライン）として出る。**
   `blur(0px)` や、アニメの残りかすの `blur(0.003px)` でも出る。
   → 対処は ①フィルターを外す ②`-mt-[2px]` で 2px 重ねる。フッターと体験セクションで実施済み。
3. **`position: fixed` の要素の上では backdrop-blur が効かないことがある。**
   ぼーっとタイマーはこれで一度効かなくなった。

### スクロール演出の決まりごと（V3 で制定）

- **動かしてよいのは `transform` / `opacity` / `clip-path` だけ。**
  `width` / `height` を毎フレーム変えるとレイアウトが計算し直しになって
  ガタつく（体験セクションの「グラグラする」の原因はこれだった）。
- **いちばん良く見えるのは「画面の真ん中に来た時」。**
  スクロール進行度は 0＝下から入る／1＝上へ抜ける なので、**0.5 が画面中央**。
  `[0, 0.5] → [0, 1]` に読み替えて、中央で完成してそのまま保つ。
- **進行度の入力範囲は必ず 0〜1 の増加順**。マイナスを入れるとページが落ちる
  （WAAPI の "Offsets must be monotonically non-decreasing"）。
- **カードの入れ替えをスクロールに乗せない（2026-10-14 ヒデさん）**。体験セクション（案2）は、スクロールで1枚ずつ切る作りが「気持ちいい体験になっていない」ため、送りボタンで好きな時に入れ替える形にした。スクロールはそのまま上下へ流す（下へ行かせない見張りも付けない）
- **送りボタンは、後ろを流れる文字の帯と同じ高さに置かない（2026-10-14 ヒデさん「左右のボタンは文字のカルーセルスライドショーに被るのでやめたい」）**。体験セクション（案2）の帯は束の上下の真ん中を通るので、束の左右（上下の真ん中）に置くと文字に重なる。送りボタンは束の下に置く

### PC の紙の縮め方（2026-10-20）

- PC は 1512×982 の紙を画面に合わせて縮める。**縮め方は zoom（Stage.tsx）。transform: scale に戻さない**。transform だと本物の Chrome（GPU）で文字・図形がいったん絵に焼かれて縮められ、倍率が1以外の画面でボケる（FIXLOG 2026-10-20）

### フッターの上の形（2026-10-28 決定・全ページ共通）
- **決まり**：中身の終わりまで真っ白にしてからグラデをかけない。トップと同じく、フッターを本文の裏へ潜り込ませ、本文の白い箱の下の方を透明にして、本文の裏からグラデ（白がゆっくり明ける）を始める。中身の終わりで白はまだ8割ほど残り、そこから淡い空へゆっくり晴れる（ヒデさん「いい感じです。下層ページも同じような構成ならフッターの上の境界線はこの形に。スマホも合わせたい」）
- **作り**：`<SiteFooter overlap="wide" />`＋本文の白い箱に `background: linear-gradient(to bottom, #fff calc(100% - var(--ft-overlap-wide)), transparent calc(100% - var(--ft-overlap-wide)))`（`relative z-10`）。新しい下層ページもこの2つで作る
- **値**：潜り込み `--ft-overlap-wide` … PC（フッターが横並び・1200px 以上）600px／スマホ・タブレット 360px 🟡。グラデの長さ … PC は画面の130%（トップと同じ `--ft-fade-h`）／スマホ・タブレットは画面の85%・上限848px（`--ft-fade-h-narrow`）🟡。作字は PC はグラデが消えきってから 64px 下／スマホ・タブレットは白が25%まで薄くなった所から。スマホ・タブレットの詳しいページは本文の箱の下の余白も 32px
